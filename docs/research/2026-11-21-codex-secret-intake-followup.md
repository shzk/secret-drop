# Secret Drop — защищённый ввод в Codex после проверки MCP Form

21.11.2026 · Исследовательская ветка · Результат проверки и варианты дальнейшей работы

## Что подтверждено

- Релиз Secret Drop Codex 0.6.0 уже даёт одно защищённое окно AppKit для существующего секрета на Mac, проверку выбранного назначения и запись через существующий writer. Результат для агента содержит имена и статусы. Права 0600 защищают от других пользователей ОС, но не от агента, которому разрешено читать этот файл. [Документация адаптера](../../codex/secret-drop/README.md).
- В Claude Code плашка над composer и перехват отправки — функции mod, который сам принимает ввод. В Codex публичный аналог этой точки расширения для стороннего плагина не найден. [Сравнение исходников](2026-11-21-claude-mods-vs-codex-secure-input.md).
- Прежний E2E Codex Desktop подтвердил встроенную Form для несекретного назначения. Отдельный тест app-server 0.163.0 показал, что публичный маркер из Form может попасть в ответ инструмента. Связка Form → AppKit-мок → реальный writer проверена на уровне кода. В ChatGPT Work через вручную добавленный MCP в предыдущем чате подтверждался только фиктивный путь, записи не было. [Desktop pilot](2026-11-21-codex-form-host-pilot.md) · [Тест публичного маркера](2026-11-21-public-marker-vs-secure-intake.md).
- Спецификация MCP 2026-07-28 исключает credentials из Form, даже при визуальном маскировании. URL mode запрашивает согласие на внешнее действие. Статус записи должен прийти отдельно от механизма, который действительно записал значение. [MCP Elicitation](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation).

## Что добавила эта проверка

**У OpenAI уже есть публичный образец безопасной выдачи нового ключа.** В OpenAI Developers для Codex picker собирает имя ключа и проект, отдельная локальная MCP Form подтверждает файл. Локальный помощник создаёт пару ключей, коннектор получает публичный JWK и возвращает зашифрованный новый OpenAI API key. Помощник расшифровывает результат на месте, пишет в выбранный файл и выводит только метаданные. Это основание для похожего процесса с поставщиком, у которого есть API выдачи ключей. Публичного универсального поля, принимающего уже существующие ключи произвольных провайдеров, из этого примера не следует. [Документация OpenAI](https://developers.openai.com/learn/developers-codex-plugin) · [Публичная реализация](https://github.com/openai/plugins/blob/main/plugins/openai-developers/skills/openai-platform-api-key/SKILL.md).

Локально на Linux с Node v24.22.3 прошли 17/17 выбранных тестов неизменённых исходников OpenAI. Проверены публичный запрос, форма назначения и её отмена, расшифровка и запись синтетического значения без его вывода, права файла и отказ от небезопасных путей. Picker, сетевой коннектор, создание реального ключа и Desktop UI в этот прогон не входили. Команда из корня openai/plugins:

```sh
node --test --test-name-pattern='^(prepare writes|local destination confirmation|decrypt )' plugins/openai-developers/tests/openai-platform-api-key.test.mjs
```

Git blob SHA исходников: helper `e05bea1087f2c8afd711520f86a925154b0d2e94`, tests `5435f0efebb7b16bef5afdce48b5df1e13b23654`, MCP server `48fe359fcaf0cefda10ab78756981ba9c6f9f5d2`.

**URL mode стоит проверять на конкретном хосте и транспорте.** В доступном Linux Codex CLI `0.172.0-alpha.2` команда `codex features list` показала `auth_elicitation: stable, true` и `tool_call_mcp_elicitation: stable, true`. Это более свежее наблюдение для конкретной сборки, чем описание в issue #29344. Тестовый app-server завершился до рукопожатия. Сначала не открылась SQLite по стандартному пути, после переноса SQLite в scratch процесс завершился с `Read-only file system`. Протокольного результата этот запуск не дал. В открытом issue #40657 описана отдельная несовместимость stateless HTTP 2026-07-28 в более старых версиях. Она не доказывает отказ обычного stdio или текущего ChatGPT Work. [Код Codex](https://github.com/openai/codex/blob/main/codex-rs/core/src/config/mod.rs) · [#29344](https://github.com/openai/codex/issues/29344) · [#40657](https://github.com/openai/codex/issues/40657).

## Решение для дальнейшего пилота

| Цель | Вариант | Что пока открыто |
| --- | --- | --- |
| Положить существующий ключ в проект на Mac | Оставить один AppKit-диалог и текущий writer. Вторая Form повторяет уже существующее подтверждение | Работа из конкретной Work-сессии зависит от доступа к локальному MCP и реального Mac-окружения |
| Запустить сценарий из ChatGPT Work или другого клиента | Адресный тест стандартного URL mode с безвредной страницей и отдельным подтверждением завершения | Поддержка в нужной сессии, фактический браузер, привязка пользователя и назначение записи. HTTPS-страница сама не получает доступ к Mac checkout или облачному контейнеру |
| Выдать новый ключ OpenAI | Использовать официальный OpenAI Developers, если доступен и подключён; взять схему за образец для других провайдеров только при наличии API выдачи | Проверка сетевого end-to-end отдельно от синтетических тестов |
| Пользоваться ключом с изоляцией от shell агента | Хранить в выбранном хранилище или на стороне целевого процесса, возвращать агенту только результат разрешённой операции | Это отдельное требование. Файл в доступном агенту checkout и переменная окружения общего shell такой изоляции не дают |

Для URL-пилота сначала использовать существующий probe или его изолированную копию. Вход и завершение — публичные фиктивные данные. Проверить открытие внешнего URL, Cancel, Accept без открытия/сохранения и одно фактическое подтверждение завершения, исключив двойное применение при повторе. Для следующего шага держать значение вне MCP аргументов, ответов, URL, логов и браузерной автоматизации агента. Если нужен локальный файл, доверенный локальный процесс должен сам проверить назначение и выполнить запись. Для удалённой цели нужны подтверждённая авторизация, привязка к пользователю и утверждённому назначению на стороне получателя. До результата пилота не требуется новый постоянный веб-сервис.

Codex Cloud (Legacy) документирует Secrets только для setup phase. Это отдельный способ, когда ключ нужен при установке; перенос в доступный агенту файл меняет границу защиты. [Codex Cloud](https://learn.chatgpt.com/docs/environments/cloud-environment). Для Work Cloud возможность обращения к компьютеру документирована отдельно и зависит от допуска рабочего пространства, настроек desktop и подключённого устройства. На аккаунте пользователя такая связь с Secret Drop в рамках этой проверки не подтверждалась. [Work local access](https://learn.chatgpt.com/docs/enterprise/cloud-local-access).
